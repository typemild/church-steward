# UI 가이드라인

화면을 만들거나 고칠 때 지킬 규칙이다. 화면들이 같은 모양과 같은 키보드·마우스 동작을 가질 수 있도록 본 규칙을 준수해야 한다.
구조와 도메인 규칙은 [아키텍처](architecture.md)에 있다.

## 디자인 원칙

- **깔끔하고 단순하게**: 불필요한 장식을 빼고 여백을 충분히 두어 정보를 읽기 쉽게 한다.
- **부드럽고 전문적으로**: 딱딱한 업무용 프로그램보다는 부드러운 색감과 둥근 모서리로 편안하게 보이게 한다.
- **시각적 위계**: 색과 글자 굵기로 사용자가 먼저 할 일(주 동작)을 분명히 알려 준다.
- **크기**: 메인 화면의 콘텐츠 영역은 720×600이다.

## 색과 글꼴

- 색은 `ui.util.UIColors`, 글꼴은 `ui.util.UIFonts`에 정의된 것만 쓴다. `new Color(...)`를 직접 쓰지 않는다.
- 예외로, 보고서 지면의 글꼴과 기본 글자 크기(pt)는 `ui.view.report.layout.ReportFonts`가 관리하고(사용자가 고른 글꼴과 조정한 크기는 `ReportStyle`이 적용한다), 보고서의 색은 `UIColors.REPORT_*`를 쓴다.
- 포커스 색은 Primary 색이다(`ChurchStewardApplication.main`에서 FlatLaf를 설정하기 전에 지정한다).

## 공용 컴포넌트

기본 Swing 컴포넌트 대신 아래 공용 컴포넌트를 쓴다(`org.church.steward.ui.component`).

| 종류 | 컴포넌트 |
|---|---|
| 버튼 | `PrimaryButton`(주 동작), `SecondaryButton`(그 밖의 버튼), `IconButton`(글자 없이 아이콘만) |
| 입력란 | `StyledTextField`, `StyledTextArea`, `AmountField`(금액), `StyledComboBox`, `StyledCheckBox`, `StyledDatePicker`, `ValidatedPasswordField` |
| 레이블 | `TitleLabel`(제목), `SubTitleLabel`(부제목), `SectionHeaderLabel`(영역 머리말), `DescriptionLabel`(내용), `FieldLabel`(입력란), `SubFieldLabel`(덜 중요한 입력란), `BadgeLabel`(배지) |
| 패널 | `WarningNoticePanel`(경고 아이콘이 붙은 주의 사항) |
| 표 | `ListTable`(목록 표), `TreeTable`(접고 펼치는 표), `ExpandCollapseAllButton` |

`AmountField`는 생성자 옵션으로 빈 값을 허용할 수 있으며, 이때 `getAmount()`는 `null`을 반환한다(검색 조건처럼 비워 둘 수 있는 금액에 쓴다).

## 입력란의 최대 길이

저장되는 글자를 받는 입력란(`StyledTextField`, `StyledTextArea`)은 `setMaxLength`로 최대 길이를 지정한다. 넘치면 저장할 때 쿼리 오류가 나기 때문이다(검색란처럼 저장하지 않는 입력란은 지정하지 않는다).

- 길이 값은 화면에 직접 적지 않고 기능별 제약 클래스(`ContactConstraints`, `FinancialRecordConstraints`, `BudgetConstraints`, `FiscalYearConstraints`, `UserConstraints`)의 상수를 쓴다. 엔터티의 칼럼 길이와 서비스의 검증도 같은 상수를 쓴다.
- 넘치는 글자는 거부하지 않고 남은 칸만큼만 잘라 넣으며(`MaxLengthDocumentFilter`), 잘리면 입력란 아래에 "최대 N자까지 입력할 수 있습니다." 안내를 3초 동안 띄운다(`InputHintPopup`). 입력기가 조합 중인 글자는 제한하지 않고 확정될 때 자른다.
- `setText`로 넣은 값도 잘린다. 다만 입력란이 화면에 보이기 전이면 안내는 뜨지 않는다.
- 입력란 아래에 잠깐 띄우는 안내는 `InputHintPopup`으로 통일한다(`ValidatedPasswordField`의 한/영 전환 안내도 이것을 쓴다).

## 레이아웃과 기타 스타일

- 입력 폼은 `GridBagLayout`으로 레이블과 입력란을 정렬한다.
- 컴포넌트 사이의 간격은 8~25px로 하고, 화면 가장자리에는 30px 이상의 `EmptyBorder`를 둔다.
- 주 버튼은 아래쪽 가운데나 오른쪽에 둔다.
- 진행 표시는 Primary 색의 indeterminate 진행 막대를 쓴다.
- 아이콘은 Ikonli의 FontAwesome 5 Solid를 `FontIcon.of(FontAwesomeSolid.X, size)`로 쓴다. Font Awesome Free의 라이선스(아이콘 CC BY 4.0, 글꼴 OFL 1.1)는 라이선스 리포트에 나오지 않으므로 프로그램 정보의 오픈소스 목록에 직접 넣어 두었다(`ProgramInfoServiceImpl`).
- **프로그램 아이콘**: 부모 창이 없는 창(`MainView`, `LoginView`, `DatabaseInitView`, `DatabaseRestoreView`)은 `AppIcons.apply(this)`를 호출한다. 부모 없는 메시지 창과 macOS Dock은 `main`의 `AppIcons.install()`이 맡고, 부모 창이 있는 다이얼로그는 부모의 아이콘을 따른다. 새로 부모 없는 창을 만들면 `apply`를 호출한다.

## 입력란의 테두리와 포커스

공용 입력 컴포넌트는 FlatLaf의 테두리(둥근 모서리, 포커스를 받으면 색이 바뀜)를 그대로 쓴다.

- `setBorder`로 테두리를 바꾸지 않는다. 포커스 표시가 사라져서, 콤보박스나 읽기 전용 입력란(예산 선택 박스)처럼 커서가 보이지 않는 입력란은 포커스를 알아볼 수 없게 된다. 안쪽 여백은 텍스트 입력란이면 `setMargin`, 콤보박스면 `FlatClientProperties.STYLE`의 `padding`으로 준다.
- 날짜 피커는 LGoodDatePicker가 입력란에 단 사각 테두리를 FlatLaf 테두리로 되돌린다(`StyledDatePicker#zDrawTextFieldIndicators`).
- 여러 컴포넌트로 된 입력란(`ContactChipField`)은 바깥 패널에 `FlatTextBorder`를 달고 `FlatClientProperties.COMPONENT_FOCUS_OWNER`로 안쪽 입력란의 포커스를 따르게 하며, 배경도 둥글게 직접 그린다.
- 여러 줄 입력란은 `JScrollPane`에 넣는다. 스크롤 패인의 FlatLaf 테두리가 포커스를 표시한다.

**포커스 테두리는 입력/수정 다이얼로그에서만 보인다.** 목록 화면의 검색란, 사이드바의 회계 연도 선택란, 목록 표에 포커스 테두리가 생기면 어색하기 때문이다.

- 공용 입력 컴포넌트는 만들 때 `FocusIndicator#hide`로 포커스 표시를 끄고, `DialogKeyHandler`가 `addField`로 등록한 입력란만 `FocusIndicator#show`로 켠다.
- `DialogKeyHandler`를 쓰지 않는 기동 화면(로그인, 최초 실행, 복원)은 입력란마다 직접 켠다.
- 표에는 `FocusIndicator`를 쓰지 않는다(FlatLaf가 같은 값으로 표의 선택 색도 정한다). 대신 `ListTable`이 감싼 스크롤 패인의 테두리를 회색 선(`UIColors.BORDER`)으로 바꾼다.
- 공용 컴포넌트가 아닌 표나 입력란(`LicenseTab`, `FileStepPanel`의 스피너)은 각 화면에서 처리한다.

## 목록 표

- 목록 표는 `JTable` 대신 `ListTable`을 쓴다.
- 모양의 기본값은 `ListTable`이 정하므로 화면에서 다시 지정하지 않는다: 기본 글꼴, 행 높이(`ListTable.DEFAULT_ROW_HEIGHT`, 기본 글자 크기의 2.3배), 격자 없음, 스크롤 영역 높이 채우기, 머리글 순서 변경 끄기. 선택 방식(한 행/여러 행)은 화면마다 정하고, 행 높이가 달라야 하는 화면(회계 연도 관리처럼 두 줄짜리 칸)만 다시 지정한다.
- 선택된 행을 다시 클릭하거나 표의 빈 영역을 클릭하면 선택이 풀린다. 한 행만 선택된 상태에서 Ctrl/Shift 없이 그 행을 클릭했을 때만 풀리므로, 여러 행을 고를 수 있는 표에서도 그대로 쓴다. 선택을 풀 때는 선택 모델의 anchor와 lead도 -1로 되돌린다(그러지 않으면 마지막으로 누른 셀에 포커스 테두리가 남는다). 키보드로 이동할 때는 선택이 풀리지 않는다.
- ↓ 키는 마지막 행에서 첫 행으로, ↑ 키는 첫 행에서 마지막 행으로 넘어간다.
- 행 더블클릭은 마우스 이벤트로 직접 처리하지 않고 `ListTable#setRowDoubleClickHandler`(모델 기준 행 인덱스를 받는다)로 등록한다. 두 번째 클릭에서 풀린 선택은 표가 그 행으로 다시 잡은 뒤 처리기를 부르므로, 처리기는 선택된 행을 그대로 쓰면 된다. 편집 가능 여부 같은 조건은 처리기 안에서 확인한다.
- 처리기를 등록한 표에서는 행을 고른 채 누른 Enter도 다음 행으로 옮기지 않고 같은 처리기를 부른다. 선택은 바꾸지 않고 마지막으로 고른 행의 인덱스를 넘긴다. 선택 다이얼로그의 `pressPrimaryOnEnter`는 같은 키를 덮어쓰므로 처리기를 등록한 뒤에 호출한다.
- 셀의 툴팁은 표 모델이 `TooltipTableModel#getTooltipText`(모델 기준 행/열)로 준다. 표마다 `getToolTipText`를 재정의하지 않는다.
- 여러 건을 고를 수 있는 표에는 고르는 방법을 한 번 적는다. 맥이면 Command, 아니면 Ctrl로 적는다(Swing 표는 맥에서 Command로 한 줄씩 더 고른다).

### 접고 펼치는 표

행을 접고 펼치는 표(예산 관리, 수입/지출의 "예산별 보기")는 `TreeTable`을 쓴다.

- 모델은 `AbstractTreeTableModel`을 상속해 `setRoots`로 트리(`TreeTableNode`)를 넣는다. 펼침 상태는 노드의 키로 기억하며, 기본 펼침/접힘은 모델 생성자에서 정한다.
- 트리 칸의 값은 표시할 글자이고, 들여쓰기와 화살표는 `TreeTable`의 렌더러가 그린다. 화살표 클릭은 표가 처리하며, 화살표를 빠르게 두 번 누른 것은 행 더블클릭으로 전달하지 않는다.
- 좌/우 방향키는 칸 이동 대신 선택된 행을 다룬다. 오른쪽은 접힌 행을 펼치고, 왼쪽은 펼쳐진 행이면 접고 아니면 상위 행으로 선택을 옮긴다.
- 표 제목 바로 오른쪽에 모두 펼치기/모두 접기를 겸하는 버튼(`ExpandCollapseAllButton`)을 둔다. 펼쳐진 행이 하나라도 보이면 "모두 접기", 모두 접혀 있으면 "모두 펼치기"다. 아이콘은 누를 때의 동작이 아니라 지금 상태를 나타낸다(펼쳐진 행이 있으면 열린 폴더). 툴바의 추가·이동 버튼과 헷갈리지 않도록 툴바가 아니라 제목 옆에 둔다. 보기만 바꾸므로 읽기 전용 화면에서도 쓸 수 있다.

## 다이얼로그의 키보드 동작

다이얼로그에는 `DialogKeyHandler`를 붙인다.

- **닫기**: Esc, 창의 닫기 버튼, 취소 버튼은 모두 `requestClose()`를 거친다. 취소 버튼이 꺼져 있으면(작업 중) 닫지 않고, `trackChanges`로 지정한 입력값이 띄운 시점과 다르면 닫기 전에 확인을 받는다(데이터를 입력/수정하는 창만 지정한다). 그래서 취소 버튼에 `dispose()`를 직접 붙이지 않는다.
- **Enter**: 입력란은 화면 순서대로 `addField`로 등록한다. Enter를 누르면 켜져 있는 다음 입력란으로 옮기고, 마지막 입력란이면 주 버튼을 누른다. 여러 줄 입력란(`JTextArea`)도 `addField`로 등록하면 Tab은 포커스 이동, Enter는 다음 입력란 이동(마지막이면 주 버튼), 줄바꿈은 Shift+Enter가 된다. 입력란 오른쪽 아래에 "줄을 바꾸려면 Shift + Enter를 누르세요." 안내를 적는다(`ContactDetailDialog`의 비고).
- 여러 컴포넌트로 된 입력란(날짜 피커, `BudgetSelectBox`, `ContactChipField`)은 `CompositeInputField`로 포커스 받을 컴포넌트를 알려 준다.
- 콤보박스 목록이나 자동 완성 목록이 떠 있으면 Enter와 Esc는 목록이 먼저 처리한다. 관계자 입력란은 칩으로 확정되지 않은 글자가 남아 있으면 Enter로 다음 입력란으로 옮기지 않고 자동 완성 목록을 다시 띄운다.
- 다이얼로그가 띄운 창(메시지 창 제외)이 닫히면 마지막으로 쓰던 입력란에 포커스를 되돌린다.
- 입력란 없이 표만 있는 선택 다이얼로그는 `pressPrimaryOnEnter`로 창 어디서든 Enter를 누르면 선택한 항목으로 확인한다. 표의 행을 더블클릭해도 그 항목으로 확인한다(예산 선택/매핑 다이얼로그는 `BudgetTreePanel#setRowDoubleClickHandler`로 편집 모드의 더블클릭 수정을 대신한다).
- 조회만 하는 다이얼로그는 Esc만 붙인다.
- 기동 화면(`DatabaseInitView`, `DatabaseRestoreView`)에는 붙이지 않는다. Esc로 초기화나 복원이 취소되지 않게 하기 위함이다. 대신 두 화면은 작업하는 동안 창의 닫기 버튼을 무시한다(작업 중에 닫히면 작업이 끝나기 전에 취소로 반환되어 기동 절차가 이어지기 때문이다).

## 화면과 컨트롤러 호출

- `MainView`는 사이드바와 `CardLayout`을 가진 `JFrame`이다. 각 화면은 `MenuActivatable.onMenuSelected()`를 구현한 `JPanel` 빈이며, 이 메서드에서 데이터를 읽거나 갱신한다. 데이터 관리 메뉴는 관리자에게만 보인다.
- 컨트롤러는 `AsyncTask.run(lockTarget, backgroundWork, onSuccess, onError)`로 호출한다. 대상 컴포넌트를 끄고 대기 커서를 보여 주는 `SwingWorker` 래퍼로, EDT가 DB 작업으로 멈추지 않게 하기 위함이다.
- 메뉴 구성이나 ID 표시처럼 화면을 만들면서 바로 필요한 로그인 정보는 컨트롤러를 거치지 않고 `UserSessionHolder`에서 읽는다.

### 회계 연도 공유

대시보드, 수입/지출 관리, 보고서, 예산 관리는 같은 회계 연도를 본다. 사이드바 맨 위의 `FiscalYearSelector`가 회계 연도 목록과 선택된 회계 연도를 보관하며, 이 네 메뉴를 그 바로 아래에 이 순서로 묶고 나머지 메뉴는 구분선으로 나눈다. 각 화면은 자체 회계 연도 선택란을 두지 않고 `FiscalYearSelector#getSelectedFiscalYear()` 또는 `getSelectedFiscalYearId()`를 읽는다.

- 회계 연도가 바뀌면 `MainView`가 현재 보이는 화면이 위 네 화면 중 하나일 때만 그 화면의 `onMenuSelected()`를 다시 호출한다. 보이지 않는 화면은 알림을 받지 않으므로, 회계 연도에 딸린 상태가 있으면 `onMenuSelected()`에서 마지막으로 조회한 회계 연도와 비교해 정리한다.
- 변경 알림은 선택된 회계 연도의 ID가 바뀔 때만 온다. 이름, 기간, 마감 여부만 바뀐 경우에는 오지 않으므로, 각 화면은 `onMenuSelected()`에서 매번 `getSelectedFiscalYear()`를 다시 읽어 기간 제한과 편집 가능 여부를 맞춘다.
- 선택한 회계 연도는 사용자 설정에 저장되어 다음 실행 때 초기값이 된다. 저장된 회계 연도가 삭제되었으면 가장 최근 회계 연도로 대신한다.
- 선택란의 항목은 두 줄로 그린다(`FiscalYearComboRenderer`). 윗줄은 이름, 아랫줄은 "25.12.01 ~ 26.11.30"처럼 줄인 기간이고, 마감된 회계 연도는 이름 앞에 자물쇠 아이콘을 붙인다.
- "회계 연도" 레이블 오른쪽의 톱니바퀴 버튼은 설정의 회계 연도 관리 탭으로 이동한다. 그래서 회계 연도 관리 탭은 설정의 첫 번째 탭으로 고정한다. 그 탭에서 회계 연도를 바꾸면 `FiscalYearSelector#reload()`로 사이드바 목록을 갱신한다.
- **마감된 회계 연도**: 예산 관리와 수입/지출 관리는 같은 안내 문구("마감된 회계 연도입니다. 조회만 할 수 있습니다.", `ClosedFiscalYearNoticeLabel`)를 띄우고, 데이터를 바꾸는 버튼(예산 관리의 편집 툴바, 수입/지출 관리 두 탭의 추가/수정/삭제)을 끄지 않고 숨긴 뒤 그 자리에 상세 보기 버튼(수정 버튼과 같은 아이콘)을 둔다. 행 더블클릭과 Enter도 수정 대신 상세 보기를 연다. 상세 보기 다이얼로그는 수정 다이얼로그를 읽기 전용으로 바꾼 것이며(`enableViewOnly`), 제목은 "수입 상세 보기"처럼 "상세 보기"로 끝나고, 맨 위에 같은 마감 안내를 보이며, 버튼은 "닫기"뿐이다. 입력란은 끄지 않고 편집만 막아 글자를 읽기 쉽게 둔다. 조회, 보고서, 대시보드는 그대로 쓸 수 있다.

## 화면별 결정 사항

### 수입/지출 관리

- **조회 시점**: 조회 버튼을 누르거나 금액·내역·비고 입력란에서 Enter를 쳤을 때 조회한다. 예외로, 기간 단위를 바꾸거나 화살표로 기간을 옮기거나 날짜 피커로 날짜를 바꾸면 자동으로 조회하고, 회계 연도를 바꿔도 자동으로 조회한다.
- **조회 기간은 회계 연도의 기간을 벗어날 수 없다**(`PeriodSelectorPanel#setLimits`). 단위 기간이 회계 연도 기간에 걸치면 벗어난 부분을 잘라내고, 화살표는 회계 연도 기간과 겹치지 않는 쪽으로는 꺼진다. "연간"은 회계 연도 기간 전체를 뜻한다. 회계 연도를 바꾸면 조회 기간은 오늘이 속한 단위 기간으로 옮겨지며, 오늘이 기간 밖이면 기간에서 오늘과 가장 가까운 날이 기준이 된다.
- **기간 단위**: "주간"은 일요일부터 토요일까지다. 날짜 피커로 기간을 직접 바꾸면 단위와 어긋날 수 있으며, 화살표로 이동하면 단위에 맞는 기간으로 돌아온다. 시작일이 종료일보다 늦어지면 방금 바꾼 쪽에 맞춰 반대쪽을 같은 날로 옮긴다.
- **금액 조건**: "시작 금액 ~ 종료 금액" 범위이며 양 끝을 포함한다. 한쪽만 입력하면 이상/이하 조건이 된다. 시작 금액이 종료 금액보다 커도 보정하지 않는다.
- **입력 날짜**: 입력 다이얼로그의 날짜는 회계 연도 기간 안에서만 고를 수 있고(`StyledDatePicker#setDateRange`), 초기값은 오늘(기간 밖이면 가장 가까운 날)이다.
- **예산 선택**: 검색에서는 상위 예산도 고를 수 있고, 입력 다이얼로그에서는 해당 구분의 말단 예산만 고를 수 있다. 예산 선택 다이얼로그는 예산 관리의 `BudgetTreePanel`을 읽기 전용 모드로 다시 쓴다.
- **내역의 순서**: 두 탭 모두 날짜 오름차순이고, 같은 날짜에서는 ID 오름차순(입력한 순서)이다. 장부처럼 새 내역이 아래에 붙게 하기 위함이다. "건별 보기"에서 날짜 머리글로 정렬 방향을 바꾸면 같은 날짜의 내역도 함께 뒤집힌다(내림차순이면 ID 내림차순). 다른 칸으로 정렬하면 값이 같은 행은 ID 내림차순이다.
- **추가한 내역 보여 주기**: 내역을 추가하면 다시 조회한 뒤 두 탭에서 그 내역을 선택하고 보이도록 스크롤한다. "예산별 보기"는 그 예산 행을 펼친다. 조회 조건에 맞지 않아 목록에 없으면 아무것도 하지 않는다.
- **선택 합계**: "건별 보기"는 수입을 더하고 지출을 뺀다. "예산별 보기"는 예산 행과 그 하위 내역 행이 함께 선택되면 예산 행 금액만 센다.
- **관계자 입력(`ContactChipField`)**: 자동 완성 목록에서 고른 관계자만 칩으로 확정되며, 확정되지 않은 글자는 포커스를 잃으면 사라진다. 검색 조건은 단순 목록(`SimpleContactSuggester`), 입력 다이얼로그는 계층형 목록(`HierarchicalContactSuggester`)을 쓴다. 두 목록 모두 관계자를 5명까지(`ContactSuggestions.LIMIT`) 보여주고, 더 있으면 맨 아래(계층형은 "신규 추가" 아래)에 남은 건수 안내를 작은 글씨 한 줄로 오른쪽 정렬해 넣는다. 안내는 키보드로 선택되지 않고 마우스로 누르면(올리면 손 모양 커서와 밑줄) 같은 검색어로 모두 조회해 보여주며, 8개 항목을 넘으면 스크롤한다. 비고가 없는 관계자는 비고 줄을 빼므로 목록의 항목 높이는 고정하지 않는다. 대신 항목의 폭은 팝업 폭에 고정한다(`ContactSuggestions#fitToWidth`). 고정하지 않으면 비고가 긴 항목 때문에 목록이 팝업보다 넓어져 오른쪽이 잘린다. 이미 입력된 관계자는 화면에서 거르지 않고 조회에서 뺀다(그래야 5명이 채워지고 남은 건수가 맞다). 수입은 봉헌자 1명 이상에 그룹 기능을 쓰고, 지출은 수취인 1명에 그룹 기능을 쓰지 않는다.
- **칩의 이름과 툴팁**: 새로 입력한 칩은 관계자의 현재 이름을, 기존 내역의 칩은 기록 당시의 이름(스냅샷)을 보여 준다. 툴팁은 어느 경우든 관계자의 현재 정보("[구분] 이름"과 비고)를 보여 준다.

### 예산 관리

- 설정이 아닌 주 메뉴다. 수입 예산과 지출 예산을 좌우로 놓고(`BudgetTreePanel`), 예산마다 진행 현황(수입액/집행액, 달성률/집행률)을 함께 보여 준다. 표 하나의 폭이 320px 남짓이라 금액 칸과 비율 칸의 폭을 좁게 고정했다.

### 보고서의 주간 선택

- 날짜 하나만 고르게 하면 "그 날짜까지의 보고서"로 오해하기 쉬워서, 날짜 입력란 없이 "2026-10-04 (일) ~ 2026-10-10 (토)"처럼 주간의 양 끝을 글자로 보여 주고 그 오른쪽에 달력 버튼을 둔다. 달력에서는 선택된 주간 전체가 칠해져 보이며, 어느 날짜를 눌러도 그 날짜가 속한 주간이 선택된다. 좌/우 화살표로 한 주씩 이동한다.
- 다음 주간 화살표 오른쪽의 "이번 주" 버튼은 오늘이 속한 주간으로 옮긴다. 이번 주간이 회계 연도의 기간과 겹치지 않거나 이미 그 주간을 보고 있으면 꺼진다.
- 달력이 버튼을 기준으로 뜨기 때문에 공용 `IconButton`이 아니라 입력란을 숨긴 `StyledDatePicker`의 버튼을 같은 모양으로 꾸며 쓴다.
- 주간은 회계 연도의 기간을 벗어날 수 없고, 경계에 걸친 주간은 벗어난 부분을 잘라낸다.

### 보고서의 서식 줄

- 툴바의 맨 아랫줄(주간 선택 아래)에 왼쪽부터 글꼴, 세로 구분선, 글자 크기, 행 간격, "한 페이지에 맞춤" 체크박스, "초기화" 버튼을 8px 간격으로 늘어놓는다(`ReportFormatBar`).
- 글꼴, 글자 크기, 행 간격은 이름을 적지 않고 아이콘만 둔다(글꼴 `FONT`, 글자 크기 `FONT` 오른쪽에 `ARROWS_ALT_V`를 붙인 아이콘, 행 간격 `ARROWS_ALT_V` 오른쪽에 `BARS`를 붙인 아이콘). 이름은 아이콘의 툴팁으로 알린다.
- 글자 크기와 행 간격은 각각 "- 아이콘 +" 순서로 늘어놓고 흰 바탕에 회색 테두리를 두른 알약 모양으로 감싼다. 두 알약은 크기가 같도록 아이콘 칸의 폭을 넓은 쪽에 맞추고, 아이콘은 그 칸의 가운데에 놓는다. 지금 값은 레이블로 적지 않고 아이콘의 툴팁으로 보여 준다. 글자 크기는 "글자 크기: 기본", "글자 크기: +1.5pt"처럼 모든 글자에 더한 크기로, 행 간격은 "행 간격: 130%"처럼 적는다. 범위의 끝에서는 그쪽 버튼이 꺼진다.
- 한 페이지에 맞춤은 기본으로 꺼져 있으며, 켜져 있는 동안 자동으로 줄인 값을 보여 준다(직접 조정한 값과 무관하게 기본 서식에서 시작해 줄인 값이다). 이때 글자 크기나 행 간격 버튼을 누르면 한 페이지에 맞춤이 꺼지고 보이던 값에서 이어서 조정한다. 가장 작게 줄여도 한 페이지를 넘으면 서식 줄 아래에 경고 아이콘과 함께 안내를 한 줄 띄운다.
- "초기화"는 글꼴, 글자 크기, 행 간격, 한 페이지에 맞춤(꺼짐)을 기본값으로 되돌린다. 이미 기본값이면 꺼진다.
- 서식을 바꾸면 보던 페이지를 유지한 채 다시 배치한다.

### 보고서 뷰어

- 페이지 영역의 아래에 상태 줄을 둔다. 왼쪽은 페이지 목록 여닫기 버튼과 보기 유형 콤보박스, 가운데는 현재 페이지("2 / 5 페이지". 페이지별 보기에서는 처음/이전/다음/끝 버튼과 "2 / 5"), 오른쪽은 축소 버튼, 배율 콤보박스, 확대 버튼이다. 현재 페이지는 상태 줄 전체의 가로·세로 가운데에 놓는다(양옆 영역의 폭을 같게 맞춘다). 휠 확대/축소 단축키(Ctrl + 휠, 맥은 Command(⌘) + 휠)는 상태 줄에 적지 않고 확대/축소 버튼과 배율 콤보박스의 툴팁으로 알린다.
- 페이지 목록은 페이지 영역의 왼쪽에 두며 기본은 숨김이다. 페이지를 작게 줄인 그림과 페이지 번호를 세로로 늘어놓고, 현재 페이지는 Primary 색의 굵은 테두리로 표시한다.
- 배율 콤보박스는 직접 입력할 수 있다. 목록에는 "폭 맞춤", "페이지 맞춤"과 정해진 배율만 넣고, 버튼이나 휠로 정한 다른 배율은 입력란에 "130%"처럼 보여 준다. 숫자가 아닌 글자를 적으면 지금 배율로 되돌린다. 맞춤 방식일 때의 실제 배율은 툴팁으로 보여 준다.
- 페이지(종이) 위에서는 커서를 펼친 손 모양으로, 끄는 동안에는 쥔 손 모양으로 바꾼다. 종이 밖의 회색 바탕에서는 기본 커서다.
- 페이지가 영역보다 좁으면 가운데에 놓고, 넓으면 가로 스크롤 막대가 생긴다.
### 데이터 관리 화면

"백업/복원", "관계자", "예산", "수입/지출" 네 탭으로 구성한다. 수입/지출을 가져오려면 관계자와 예산이 먼저 있어야 하므로 그 순서로 둔다. 관계자, 예산, 수입/지출 탭은 `AbstractTransferPanelView`를 상속하며 내보내기, 양식 내려받기, 가져오기를 제공한다.

- **탭의 회계 연도**: 예산 탭과 수입/지출 탭은 사이드바의 회계 연도를 쓰지 않고 탭마다 선택란을 둔다. 처음 들어올 때만 사이드바의 선택을 따른다. 관계자는 회계 연도에 속하지 않으므로 관계자 탭에는 선택란이 없고, 가져오기 화면의 제목에도 회계 연도를 적지 않는다.
- **가져오기는 모달 다이얼로그가 아니다**: 가져오는 도중에 다른 메뉴에서 기존 데이터를 확인하거나 고칠 수 있어야 하는데, 모달은 메뉴 이동을 막기 때문이다. 그래서 첫 화면과 가져오기 화면을 `CardLayout`으로 번갈아 보여 준다. 진행 상태는 메모리에만 있으므로, 진행 중에 창을 닫으면 `MainView`가 확인을 받는다.
- **공용 부분**(`ui/view/datamanagement/importing`): `AbstractImportPanel`이 제목, 단계 표시, 단계 전환, 알림 문구, 이전/다음 버튼을 맡고, 분석과 반영을 하는 동안 버튼 줄 가운데에 진행 표시를 보여주며 버튼을 끈다(`runTask`). 단계마다 할 일은 하위 클래스(`ContactImportPanel`, `BudgetImportPanel`, `RecordImportPanel`)가 정한다. 상태는 화면 컴포넌트와 분리해 세션 객체(`ImportSession`과 그 하위 클래스)가 가진다.
- **다시 들어오면 다시 분석한다**: 사용자가 정한 것(파일 내용, 열 지정, 직접 한 매핑과 선택)은 유지하고, 달라진 것이 있으면 알린 뒤 검토 단계에서 다시 확인하게 한다. 회계 연도가 삭제되었으면 가져오기를 취소한다.
- **반영 오류**: `BackupOutdatedException`을 받으면 백업을 다시 받게 하고, `ImportStateChangedException`을 받으면 다시 분석해 검토 단계로 돌아간다.
- **수입/지출의 매핑 단계**: 구분, 예산, 관계자를 탭으로 나눠 파일의 값마다 한 줄씩 보여 준다. 구분이 정해져야 예산과 관계자의 매핑 항목이 생기므로 구분 탭을 맨 앞에 둔다. 구분 탭에는 구분 칸이 없다(구분 자체를 정하는 곳이라 적을 값이 없다). 예산 선택(`BudgetMappingDialog`)은 `BudgetTreePanel`을 편집 모드로 띄워, 고르면서 예산을 고칠 수 있게 한다. 다이얼로그에서 한 변경은 즉시 저장되므로, 닫은 뒤에는 고른 것이 없어도 다시 분석한다.
- **검토 단계**: 중복 의심인 행은 기본 선택에서 빠진다. "기본 선택으로" 버튼은 직접 바꾼 선택을 버리고 이 처음 선택(오류와 중복 의심을 뺀 모든 행)으로 되돌린다. 전체 체크와 해제는 따로 버튼을 두지 않고 표 머리글의 체크박스로 한다.
- **검토 표의 체크박스**(`CheckableImportTable`, 가져오기 전용): 모델의 첫 칸을 체크박스 칸으로 쓰며 체크 상태는 모델(`CheckableTableModel`, 실제로는 세션)이 가진다.
  - 체크박스(칸 가운데의 아이콘)를 누르거나 Space를 누르면 체크가 바뀌고, 행 선택은 바뀌지 않는다(머리글 체크박스와 "기본 선택으로"도 마찬가지). 체크박스 칸이라도 체크박스 바깥을 누르면 다른 칸처럼 행을 고르고, 머리글 칸의 체크박스 바깥은 눌러도 아무 일도 없다. 그래서 체크가 바뀌면 표 전체를 다시 읽게 하지 않고 행만 다시 그린다.
  - 머리글의 체크박스는 체크할 수 있는 행이 모두 체크되었을 때만 체크로 보인다. 체크로 보일 때 누르면 모두 해제하고, 아닐 때(일부만 체크된 때 포함) 누르면 모두 체크한다.
  - 체크할 수 없는 행(오류 행)은 꺼진 체크박스로 그린다.
  - 칸 폭은 세 가지로 정한다. 체크박스 칸은 고정(`setCheckColumnWidth`), 창이 커지면 함께 넓어지는 칸(`setGrowingColumnWidth`), 창이 커져도 넓어지지 않는 칸(`setNonGrowingColumnWidth`, 행 번호·상태처럼 내용 길이가 일정한 칸)이다. 체크박스 칸을 뺀 모든 칸은 사용자가 폭을 바꿀 수 있다(넓어지지 않는 칸은 기본 폭의 3배까지).
  - 공용 표가 아니므로 다른 메뉴의 표에는 쓰지 않는다. 머리글의 정렬 아이콘을 그리지 않으므로 정렬하는 표에도 쓰지 않는다.
